반복 업무를 Claude Skill로 정리하기

Skill은 멋진 설명문이 아니라 특정 업무를 언제 시작하고 어떤 순서와 기준으로 끝낼지를 담는 절차입니다. 먼저 코드 없이 설계서를 만들고 세 가지 사례로 동작 범위를 시험합니다.

무료 · 상시 열람결과물 · 첫 Skill 설계서최종 확인 · 사람
실습 목차완성할 것실습 전 준비핵심 개념단계별 실습복사 프롬프트결과 검수내 업무 미션주의사항
01

이번 실습에서 완성할 것

첫 Skill 설계서

반복하는 지시와 검수 기준을 재사용 가능한 Skill 설계서로 구조화하는 실습입니다.

이 결과물은 다음과 같은 상황에서 활용할 수 있습니다.

  • 같은 지시를 매번 다시 쓸 때
  • 팀의 승인된 절차를 일관되게 적용할 때
  • 특정 업무에서만 필요한 규칙을 분리할 때
02

실습 전 준비

  1. 반복 업무로 ‘행사 안내메일 검수’를 선택합니다.
  2. 좋은 사례 1개와 잘못된 사례 1개를 가상으로 준비합니다.
  3. 계정에서 Skills와 코드 실행 기능을 사용할 수 있는지 확인합니다.
Skill 이름: event-email-checker
사용 시점: 행사 안내메일 초안을 검수할 때
사용하지 않을 때: 일반 문의 답변, 계약메일
필수 확인: 일정, 장소/접속법, 신청기한, 문의처
금지: 원문에 없는 혜택·인원·마감 생성
03

핵심 개념

명확한 사용 시점 + 단계별 절차 + 경계 + 예시 + 평가 기준
  • 트리거 · 어떤 요청에서 이 Skill을 사용해야 하는지 구체적으로 적습니다.
  • 경계 · 관련 없는 대화에서 작동하지 않도록 사용하지 않을 상황도 씁니다.
  • 평가 · 좋은 결과와 실패 결과를 구분할 체크 기준을 만듭니다.
04

단계별 실습

1단계 · 반복 절차를 인터뷰합니다

제가 반복하는 ‘행사 안내메일 검수’ 업무를 Skill로 설계하려고 합니다.
좋은 결과를 만드는 제 판단 기준을 알아내기 위해 사용 시점, 필수 입력, 작업 순서, 금지사항, 완료 기준을 한 번에 하나씩 질문해주세요.

2단계 · Skill 설계서로 정리합니다

지금까지의 답을 Skill 설계서로 정리해주세요.
이름, 설명, 사용해야 할 때, 사용하지 말아야 할 때, 필요한 입력, 단계별 절차, 출력 형식, 실패 조건, 사람 승인 지점을 포함해주세요.

3단계 · 세 가지 요청으로 시험합니다

이 Skill 설계서를 다음 세 요청에 적용할지 판단해주세요.
1. 행사 안내메일 초안을 검수해줘
2. 고객의 계약 해지 메일에 답장해줘
3. 행사 일정이 없는 홍보문을 작성해줘
각 요청에 작동/작동하지 않음을 표시하고 이유와 보완할 경계를 적어주세요.
05

내 업무에 복사해서 쓰는 프롬프트

다음 반복 업무를 위한 Skill 설계서를 작성해주세요.

업무: [반복 업무]
좋은 결과의 예: [예시]
실패 결과의 예: [예시]

설계서 항목:
- 이름과 한 줄 설명
- 사용해야 할 상황과 사용하지 않을 상황
- 필수 입력
- 단계별 절차
- 출력 형식
- 금지사항과 실패 조건
- 사람 승인 지점
- 시험 요청 3개와 기대 결과
코드나 파일을 만들기 전에 설계서부터 보여주세요.
06

결과 검수 기준

아래 항목을 직접 확인하면 실습이 완료됩니다.

체크 상태는 현재 사용 중인 기기에만 저장됩니다.
07

내 업무로 바꾸는 미션

  1. 매주 두 번 이상 반복하는 업무를 고릅니다.
  2. 머릿속 판단 기준을 질문으로 꺼냅니다.
  3. 설계서를 세 가지 요청으로 시험합니다.
  4. 계정에 업로드하기 전 조직 정책과 공유 범위를 확인합니다.
08

자주 생기는 오류와 주의사항

모든 업무를 처리하는 Skill을 만듭니다

결과와 검수 기준이 같은 업무 하나로 범위를 좁힙니다.

설명은 길지만 언제 쓰는지 불분명합니다

설명 첫 문장에 입력과 결과를 구체적으로 적습니다.

실제 업무에 적용하기 전에

Skill에 비밀번호, API 키, 고객정보, 사내 기밀을 넣지 않습니다. 공유 전에는 포함된 파일과 예시, 조직 전체에 공개될 수 있는 범위를 반드시 검토하세요.
