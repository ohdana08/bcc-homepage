LEVEL 3 · 25분 실습

한 번의 프롬프트보다 작업 흐름 만들기

좋은 결과를 한 번의 긴 요청에 기대지 않습니다. 입력 확인, 부족한 정보 질문, 계획 승인, 초안 작성, 사실 검수, 최종 저장을 분리해 어디서 오류가 생겼는지 알 수 있게 만듭니다.

무료 · 상시 열람결과물 · 단계형 업무 절차최종 확인 · 사람
실습 목차완성할 것실습 전 준비핵심 개념단계별 실습복사 프롬프트결과 검수내 업무 미션주의사항
01

이번 실습에서 완성할 것

단계형 업무 절차

자료 확인부터 초안과 검수까지 반복 가능한 단계형 업무 절차로 바꾸는 실습입니다.

이 결과물은 다음과 같은 상황에서 활용할 수 있습니다.

  • 결과가 매번 다른 반복 업무
  • 자료가 많고 중간 판단이 필요한 업무
  • 동료에게 업무 방식을 전달해야 할 때
02

실습 전 준비

  1. 반복 업무로 ‘인터뷰 기사 초안’을 선택합니다.
  2. 가상의 인터뷰 메모와 기사 형식 기준을 사용합니다.
  3. 결과가 아닌 실제 작업 순서를 먼저 떠올립니다.
입력: 인터뷰 메모, 인물 소개, 기사 형식
출력: 1,200자 인터뷰 기사 초안
중간 확인: 인용문, 직함, 날짜
금지: 메모에 없는 경력이나 발언 생성
최종 승인: 편집자
03

핵심 개념

입력 확인 → 질문 → 계획 승인 → 초안 → 근거 검수 → 저장
  • 중간 산출물 · 파일 목록, 누락 질문, 개요처럼 다음 단계 판단에 필요한 결과를 남깁니다.
  • 정지 조건 · 정보가 충돌하거나 근거가 없으면 다음 단계로 넘어가지 않습니다.
  • 재현 가능성 · 다른 사람이 같은 입력으로 따라 할 수 있는 순서와 기준을 적습니다.
04

단계별 실습

1단계 · 실제 업무 순서를 인터뷰합니다

제가 인터뷰 기사 초안을 만들 때 실제로 어떤 판단을 하는지 알아내고 싶습니다.
입력자료 확인, 질문, 개요, 인용 검수, 초안, 최종 승인 순서에 대해 한 번에 하나씩 질문해주세요.

2단계 · 단계와 정지 조건을 작성합니다

답변을 바탕으로 단계형 업무 절차를 작성해주세요.
각 단계에 입력, 수행할 일, 중간 산출물, 완료 기준, 작업을 멈춰야 할 조건, 다음 승인자를 표시해주세요.

3단계 · 가상 오류로 절차를 시험합니다

인터뷰 메모의 직함이 두 곳에서 다르고 날짜가 빠진 상황을 가정해주세요.
절차의 어느 단계에서 발견하고 어떻게 멈춰야 하는지 시뮬레이션하고, 발견되지 않는다면 절차를 수정해주세요.
05

내 업무에 복사해서 쓰는 프롬프트

다음 반복 업무를 재현 가능한 절차로 바꿔주세요.

업무: [업무]
입력: [자료]
최종 결과: [결과물]
최종 승인자: [사람]

먼저 제 판단 과정을 질문으로 확인한 뒤, 각 단계의 입력·행동·중간 산출물·완료 기준·정지 조건·승인자를 표로 작성해주세요. 정보가 충돌하거나 근거가 없으면 다음 단계로 넘어가지 않도록 해주세요.
06

결과 검수 기준

아래 항목을 직접 확인하면 실습이 완료됩니다.

체크 상태는 현재 사용 중인 기기에만 저장됩니다.
07

내 업무로 바꾸는 미션

  1. 결과가 자주 달라지는 업무 하나를 고릅니다.
  2. 내 판단 순서를 Claude의 질문으로 꺼냅니다.
  3. 정지 조건을 최소 세 개 만듭니다.
  4. 동료가 절차만 보고 따라 할 수 있는지 검토합니다.
08

자주 생기는 오류와 주의사항

절차가 결과 예시만 설명합니다

각 단계에서 무엇을 확인하고 언제 멈추는지를 추가합니다.

모든 판단을 AI에 넘깁니다

공개·계약·금액·사람 평가처럼 책임이 큰 결정은 승인 단계로 남깁니다.

실제 업무에 적용하기 전에

단계형 절차가 조직의 승인 절차를 대체하지 않습니다. 자동화를 연결하기 전에는 가상 자료로 오류 상황을 시험하고 사람의 중지 권한을 남겨두세요.
