# 100만 원 실매출 런북

## 성공 정의

- `SALES_METRICS.sql`의 `verified_revenue_krw`가 1,000,000원 이상
- 검증된 외부 고객이 실제 결제한 금액만 포함
- 내부 테스트, 0원 수강권, 환불, `manual-test` 주문 제외
- 페이지 배포, 메시지 발송, 신청 수는 완료 기준이 아니다.

## 승인 1 — 공개 전환

대표가 아래 세 가지를 함께 또는 개별 승인한다.

1. Git main 반영 및 운영 배포
2. Supabase 상품 `ai-workroom-pilot` 149,000원 활성화
3. 카카오톡 채널 457명 1차 메시지 발송

카카오 관리자에서 발송비가 표시되면 결제 전에 금액을 다시 승인받는다.

- [ ] `https://bccconsulting.kr/ai-workroom-pilot.html` HTTP 200
- [ ] 모바일 가로 넘침 없음
- [ ] `내 업무 무료 진단받기` 버튼이 신청 폼으로 이동

- [ ] 결제 버튼은 개인정보·약관·환불 동의 전 비활성화

## 발송 후 0~24시간

- 카카오 발송 성공·실패·차단 수 기록
- GA4에서 `utm_content=launch_01` 방문 확인
- 모든 신청을 `LEAD_TRIAGE.md`로 분류
- 대표 승인 전 외부 답변·할인·결제 링크 발송 금지
- 실결제가 생기면 주문별 감사 목록과 토스 관리자 승인금액 대조

### 24시간 판단

- 방문 50명 미만: 제목·도달·발송 시간 문제로 보고 메시지 첫 두 줄을 바꾼다.
- 방문 50명 이상, 신청 2명 미만: 랜딩의 고객 문제와 결과물 설명을 바꾼다.
- 신청은 있지만 대부분 부적합: 예시를 좁히고 대상 조건을 더 선명하게 한다.
- 적합 신청은 있지만 범위 확인 답변이 없음: 질문 수와 응답 마찰을 줄인다.

## 24~48시간

- 실제 질문과 거절 이유를 빈도순으로 묶는다.
- 질문이 있으면 그 질문에 답하는 2차 메시지를 작성해 대표 승인을 받는다.
- 질문이 전혀 없으면 `KAKAO_CAMPAIGN.md` 기본 2차안을 사용하되 발송 승인과 비용 승인을 다시 받는다.
- 첫 결제 전에는 새 상품이나 VOD 전체 재제작을 시작하지 않는다.

### 48시간 판단

- 적합 고객 4명 이상, 결제 0명: 가격·신뢰·일정·결제 마찰 중 무엇인지 직접 질문한다.
- 결제 1명 이상: 첫 고객 납품을 우선하고 사실 확인 전 후기·성과를 광고에 쓰지 않는다.
- 환불 발생: 환불 사유를 기록하고 해당 금액을 즉시 실매출에서 제외한다.

## 48~72시간

- 첫 고객이 있으면 자료 수집과 범위 확정을 완료한다.
- 첫 고객이 없으면 랜딩 전체를 다시 만들지 않고 가장 큰 병목 하나만 수정한다.
- 수정 전후 UTM을 분리해 비교한다. 예: `launch_01`, `followup_02`, `revision_01`.
