# Codex 채팅 → BCC 강의 업무 기록

## 현재 사용자의 요청

2026-11-18 사용자는 기존 문의·자료를 보존하면서 Codex 채팅에 문의 내용·파일만 전달하고, AI가 요구 정리·추천·회신·제안·후속조치를 처리하여 홈페이지에도 정리하도록 요청했다. 이 경로는 새 모델 API를 호출하지 않는다. 홈페이지는 기존 관리자 인증을 유지하며 `/admin-lecture-desk.html`에서 기록을 읽는다.

강의 전 강의안 → 현장 사진 → 종료 직후 녹음본 → 당일 블로그 작성이다. `blog_written.occurred_on`은 **실제 블로그를 작성한 한국 날짜이며 실제 강의일**이다. 공개 발행일·재저장일을 넣지 않는다. 강의 자료만 받았다고 발송·수주·입금 완료를 만들지 않는다. 과거 문의/자료를 일괄 재분류하지 않고 개별 근거를 대조한다.

## 매 문의의 실제 처리 순서

1. 받은 원문·파일을 로컬 비공개 작업 폴더에 보존한다. 파일을 배포 저장소나 공개 자산에 넣지 않는다.
2. 연결된 Supabase 도구로 **bcc-business (`jhjxrkypnigcohgnzhvq`)**의 기존 `proposal_cases`, `lecture_desk_state`를 조회한다. 기관·사업·시기·담당자·출처를 대조한다. 기관 이름만 같다고 합치지 않는다. 새 건이면 `case_id:null`, 기존 건이면 정확한 ID와 최신 `revision`을 사용한다.
3. 원문에서 확인된 사실과 모르는 내용을 분리한다. 자료 라이브러리 `proposal_knowledge`의 출처를 읽고 관련 자료를 선택한다. 파일 근거는 실제 존재/열림을 확인한다. AI 강의안에는 BCC 공통모듈·시연 원본을 적용한다.
4. Codex가 직접 `prepared.summary/questions/recommendation/email_subject/email_body/proposal_text/materials/next_action`을 준비한다. 최소한의 확인 질문만 남기고 가능한 준비는 계속한다. 비용이 발생하는 홈페이지의 과거 `generate` API를 대신 호출하지 않는다.
5. API 계약의 이벤트 JSON을 비공개 경로에 저장한다. 기관 미상은 `기관명 확인 필요`로 두고 추정 이름을 확정하지 않는다. 원문/파일을 그대로 전달받았어도 발송 사실은 별도다. 조건이 바뀌면 수정한 추천과 다음 행동도 **같은 이벤트의 prepared**에 담는다.
6. `node scripts/lecture-desk-event-sql.mjs PRIVATE_EVENT.json PRIVATE_QUERY.sql`로 검증한 SQL을 만든다. 연결된 `supabase.execute_sql`에 이 SQL을 전달한다. 사용자 원문을 SQL 문자열로 직접 이어 붙이지 않는다. 이 도구는 값과 토큰을 로그에 출력하지 않으며 SQL 자체 실행 기능은 없다.
7. `result.error`가 없는지 확인한다. 반환된 case_id/revision으로 DB를 다시 읽어 원문 이력·단계·추천/답장·날짜가 일치하는지 대조한다. 409/conflict면 최신 기록을 읽고 병합 판단 후 새 이벤트 ID를 쓴다. 응답 유실 재시도는 **동일 event_id와 동일 내용**으로 한다.
8. 성공하면 사용자에게 처리 결과와 관리자 해당 건 링크를 전달한다. 연결 실패면 저장 대기로 보고하고 준비한 자료를 보존한다. 단순 채팅 답변과 홈페이지 저장 성공을 혼동하지 않는다.

## 자료와 연락

- 기존 문의 첨부와 과거 제안은 기존 저장소를 유지한다. 새 파일은 관리자 API의 private bucket 업로드 경로를 사용한다. 2MB가 넘는 녹음·영상 원본은 기존 비공개 원본 위치에 보존하고 처리한 전사·요약을 연결한다. 원본을 웹에 업로드한 것처럼 표시하지 않는다.
- 로컬 자료 경로는 관리자에 출처로 표시할 수 있지만 인터넷 다운로드 링크로 꾸미지 않는다. 공개 URL과 로컬 출처를 구분한다.
- 섭외용 전화·이메일 설정은 빈칸이 기본이다. 기존 프로필에 연락처가 있어도 설정에 자동 복사하지 않는다. 카카오톡 CTA는 신규 문의 안내 기본값이며, 기존 이메일 협의자를 강제로 이동시키지 않는다.
- 외부 메일·카카오 메시지 발송, 자동 예약·상시 감시, 블로그 게시, 정산 장부 변경은 이 저장 경로의 기능이 아니다. 실제 발송 승인 후 전송이 확인된 경우만 `proposal_sent`를 기록한다.
- 자료 라이브러리의 제안서 템플릿은 수행실적이 아니다. `source_kind`, 원본, 근거를 확인하고 재사용한다.

## 보존과 복구

기존 문의는 `proposal_cases`, 새 처리본은 `lecture_desk_state`, 변경 원문·준비 결과 버전은 `lecture_desk_events`에 저장된다. 표시용 상태를 얻기 위해 과거 원문을 덮어쓰지 않는다. 기존 일정·정산은 기존 운영실 링크로 이어간다. UI 롤백 시 새 테이블/이력은 삭제하지 않는다.
